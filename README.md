# BraimSec 🛡️

> ⚠️ **Prototype — مش جاهز للاستخدام في بيئة إنتاج.**
> لا ترفعوا كوداً حساساً عليه. يفتقر لـ: مصادقة متقدمة، rate-limiting، عزل حاويات،
> وhold-out validation. هذا تحذير نضجٍ لا ضعف — اقرأ [القيود المعروفة](#القيود-المعروفة) قبل الاستخدام.

ماسح ثغرات SAST للمؤسسات — محرك فحص (Semgrep + gitleaks) مع طبقة AI لفهم السياق
(taint analysis) وبوابة جودة آلية تقيس الـF1 مع كل push.

## ما الذي يفعله؟

- `scanner/` — محرك الفحص: يشغّل Semgrep وgitleaks على مجلد كود ويوحّد النتائج بتقرير **SARIF 2.1.0**
- `api/` — واجهة FastAPI: رفع كود (مسار محلي أو ZIP)، تتبّع الفحوصات، استرجاع SARIF
- `ai/` — طبقة مراجعة AI: تحليل تلوث (taint analysis) يميّز الثغرة الحقيقية من الضجيج
  (مثلاً: `eval()` على `PYTHONSTARTUP` ليست ثغرة، على `request.args` ثغرة حرجة)
- `dashboard/` — لوحة تحكم عربية (RTL)
- `benchmark/` — عينة مُسمّاة + harness آلي يقيس F1 ويفشل البناء عند الانحدار

## الأرقام الحالية — بصدق

| المقياس | القيمة | الحالة |
|---|---|---|
| F1 آلي (بدون AI) | 0.846 | ✅ قابل للتكرار |
| F1 مع AI (حي، Groq) | **0.919** | ✅ قابل للتكرار — ⚠️ **n=26 فقط**، Precision=1.000 على عينة صغيرة (تحقق مطلوب) |
| المنافس (Bandit) | 0.750 | ✅ آلي |
| بوابة الانحدار: 329 قاعدة × 1334 حالة | F1=0.998 | ✅ آلية — **ليست دليل كشف** |
| Hold-out (مشروعان حقيقيان) | recall 0.333 إجمالي / 0.50 نواة SAST | ✅ قياس نظيف — ⚠️ **n=4** على النواة (ثغرة واحدة تحرك الرقم 0.25) |

**توضيح مهم:** الـ0.846 يقيس قدرة الكشف الحقيقية على كود لم تره الأداة أثناء التطوير،
بينما الـ0.998 يقيس الاتساق الداخلي (القواعد ضد اختباراتها الخاصة). رقمان مختلفان
مفاهيمياً — لا تخلط بينهما.

## الـAI يفرّق بين "كود بيعمل ثغرة" و"كود بيحكي عن ثغرة" 🧠

معظم أدوات SAST تطابق الأنماط بلا سياق: سطر `pickle.loads` يُعلَّم ثغرة أينما ظهر.
طبقة الـAI في BraimSec تقرأ السياق فعلاً — مثال موثّق من الـhold-out (dvpa):

- المحرك علَّم `pickle` على `exploit.py:8` — والـAI **رفضه** (0.95)، والسبب صحيح:
  الملف سكربت الـexploit نفسه (`pickle.dumps` لكائن محلي)، ليس sink يستقبل بيانات
  غير موثوقة. كود **يحكي عن** الثغرة، لا كود **يعمل** الثغرة.
- بالمقابل أبقى `pickle.loads` على بيانات POST حقيقية (`insecure_serials/example.py`)
  بثقة 0.96–0.99، وأبقى RCE حقيقية (`subprocess.getoutput("echo Hello " + user)`)
  بثقة 0.96.

التمييز يعمل بالاتجاهين: لا إنذار على كود الشرح، ولا تفويت للإشارة الحقيقية.
(مُلاحظ على حالات موثّقة — ليس مقياساً إحصائياً بعد.)

## القيود المعروفة

- العينة صغيرة (n=24) — التوسيع إلى 200+ ملف مخطط له
- رقم الـAI حي الآن (n=26, F1=0.919) — لكن العينة صغيرة ودقة 1.000 تستوجب التحقق
- الـhold-out موجود (Holdout-Report): recall إجمالي 0.333 / نواة SAST 0.50
- الحماية الحالية: مفتاح API + ربط محلي افتراضي + حد 50MB للـZIP + rate limiting
  (60/دقيقة لكل مفتاح) + sandbox لمسار الفحص + guards ضد ZIP bomb — كافية للتجارب المحلية فقط

### ثقوب أمنية موثّقة للـCISO 🔴

**مُصلحة بتاريخ 2026-09-26:**
1. ✅ **LFI عبر `target_path`:** كان يسمح بأي مسار محلي (`/etc/passwd`). الآن محصور
   بـsandbox (`BRAIMSEC_SCAN_ROOT`، افتراضياً `/tmp/braimsec_scans`) مع `realpath`
   validation — `..` والـsymlinks الهاربة تُرفض بـ403. مُختبر: 6/6 حالات.
2. ✅ **ZIP bomb:** حد الـ50MB كان يقيس المضغوط فقط. أُضيفت guards: حد 500MB غير
   مضغوط، 10k عضو كحد أقصى، 100MB للعضو، نسبة ضغط قصوى 100:1، رفض symlinks.
3. ✅ **Rate limiting (slowapi):** `POST /api/scans` محدود بـ60 طلب/دقيقة لكل مفتاح،
   و`POST /ai-review` بـ30/دقيقة (مكالمات LLM غالية)، و600/دقيقة افتراضياً عبر
   middleware يعمل **قبل المصادقة** (المجهولون يُحدَّدون لكل IP). التجاوز → `429`
   مع `Retry-After`. التحديد لكل مفتاح يستخدم prefix فقط — السر الكامل لا يُخزَّن.
   مُختبر آلياً: `api/test_rate_limit.py` (3/3).

**معروفة، غير مُصلحة — لا تنشر قبل معالجتها:**
4. **التحقق من نوع الملف:** الأرشيف المرفوع يُتحقق منه عبر `zipfile.is_zipfile()`
   (يفحص الـmagic bytes) — كافٍ لأننا **نفحص** الأعضاء ولا **ننفّذها**. لا حاجة
   حقيقية لـpython-magic هنا.
5. **لا عزل حاويات / timeouts كاملة / حذف مضمون** للمجلدات المؤقتة.
6. الربط بـ`127.0.0.1` مضمون فقط عند تشغيل `python3 main.py` — المشغّل يستطيع
   تجاوزه بتشغيل uvicorn على `0.0.0.0`.

## الخصوصية: أين يذهب الكود؟

- **المسار الحالي:** طبقة الـAI تعمل عبر **Groq** (API خارجي). أي كود يُرسل للمراجعة
  يغادر بيئتك — مناسب **للأكواد المفتوحة فقط**، وليس للكود الحساس أو المملوك.
- **قيد التطوير:** نموذج محلي (**Ollama**) للأكواد الحساسة — الكود لا يغادر الجهاز أبداً.
- المحرك الأساسي (Semgrep + gitleaks) يعمل محلياً بالكامل ولا يرسل شيئاً للخارج.

## التشغيل

```bash
# 1. ثبّت الأدوات
pip install semgrep
# gitleaks: https://github.com/gitleaks/gitleaks/releases

# 2. افحص كوداً
python3 scanner/scan_engine.py /path/to/code -o results.sarif

# 3. شغّل الـbenchmark (بوابة الجودة)
python3 benchmark/ci_benchmark.py --tool ours --baseline 0.80

# 4. شغّل الـAPI (يرتبط محلياً 127.0.0.1 افتراضياً)
cd api && pip install -r requirements.txt && python3 main.py
# المفتاح: يُطبع في الكونسول عند التشغيل (أو حدّد BRAIMSEC_API_KEY بنفسك)
# أرسله مع كل طلب عبر الترويسة: X-API-Key
# اللوحة: الصق المفتاح في حقل API key أعلى الصفحة
```

متغيرات البيئة: `SEMGREP_BIN`، `GITLEAKS_BIN`، `BANDIT_BIN`، `BRAIMSEC_CORPUS`
(كلها اختيارية — الافتراضي من `PATH`).
